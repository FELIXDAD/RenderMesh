# RenderMesh 使用指南

适用于 **0.3.0 / Windows x64**。命令行操作见 [CLI 指南](CLI.md)，下载见 [Releases](https://github.com/FELIXDAD/RenderMesh/releases/latest)。

## 1. 认识三个名称

- **提交电脑（Origin）**：添加工程、分配帧任务、接收输出的电脑。
- **工作电脑（Worker）**：接收任务并运行 Blender 的电脑。
- **任务包**：一次交给工作电脑的一组帧。一个任务包只启动一次 Blender。

同一台电脑可以承担前两种角色。每个任务由它自己的提交电脑管理，无需专门的中心服务器。

## 2. 安装和首次启动

1. 下载 `RenderMesh-Windows-x64-0.3.0.zip`。
2. 解压到可写的固定目录，例如 `D:\Apps\RenderMesh`。不要直接在 ZIP 内运行。
3. 双击 `RenderMesh.exe`。
4. 如果 Windows 询问网络权限，允许实际使用的专用网络或域网络。
5. 在设置页确认 Blender 路径。

RenderMesh 本身无需安装，也不需要管理员权限。Blender 的 MSI 安装可能要求系统授权。EXE 当前未做商业代码签名，Windows 可能显示未知发布者。

程序会查找标准安装目录、PATH 和程序旁的 `Blender\blender.exe`。找不到时，可在设置页：

- 选择“手动指定…”，定位到 `blender.exe`。同目录的 `blender-launcher.exe` 也会被规范化为实际 Blender 路径。
- 选择“安装 / 切换 Blender 版本”，读取官方 MSI 列表，选择版本并下载。校验通过后启动官方安装程序。

提交电脑和工作电脑应使用相同的 Blender 主、次版本。例如，5.2.x 工程应使用 5.2.x 工作电脑。需要第三方插件的工程，还应在各工作电脑准备相同插件环境。RenderMesh 不自动安装或比较工程插件。

## 3. 连接两台或更多电脑

1. 在第一台电脑查看六位匹配 ID。
2. 在其余电脑输入相同 ID。
3. 保持各台 RenderMesh 运行，等待服务器列表出现其他节点。
4. 在愿意提供算力的电脑上开启“共享本机算力”。
5. 停止使用这些电脑，等待它们达到设置的空闲阈值。默认是 180 秒。

匹配 ID 修改后，旧信任关系失效。需要继续连接的电脑必须设置相同的新 ID。

如果没有自动发现：

1. 在对方服务器列表的“本机”行查看 IPv4 地址。
2. 在本机“手动连接”输入该地址和端口，例如 `192.168.1.20:8391`。
3. 确认双方匹配 ID 一致。
4. 检查防火墙、访客 Wi-Fi 隔离和 VLAN 规则。

`127.0.0.1` 只表示当前电脑，不能用于连接另一台电脑。

| 默认端口 | 用途 |
| --- | --- |
| UDP 8390 | 局域网节点发现 |
| TCP 8391 | 状态、工程传输、任务和结果 |
| 239.255.83.90 | 局域网发现使用的组播地址，TTL 为 1 |

这些连接应仅在可信局域网内开放。不要在路由器上把端口转发到互联网。

## 4. 准备 Blender 工程

提交前，在 Blender 中完成以下操作：

1. 保存 `.blend`。
2. 设置活动场景、渲染引擎、分辨率、帧范围和步长。
3. 设置逐帧输出格式，例如 PNG 或 OpenEXR。
4. 设置主输出目录及需要使用的 File Output 节点目录。
5. 检查素材路径。准备模拟缓存及无法打包的外部文件。

推荐把需要随工程传输的文件放到同级 `tex` 文件夹：

```text
shot010/
├── shot010.blend
└── tex/
    ├── albedo.png
    └── maps/
        └── roughness.png
```

在 Blender 中使用 `//tex/...` 相对路径。RenderMesh 会把 `source.blend` 与 `tex` 一起传到工作电脑，保留相对目录关系。文件夹内不要使用目录链接或符号链接。

导入时只启动一次 Blender 来读取工程并检查素材：

- `tex` 内的素材进入工程包。
- 其他可打包素材按需写入工程副本。
- 缺失文件和无法打包的文件会产生警告。
- 原始 `.blend` 保持不变。

“无视警告”会跳过预检警告并继续准备任务。只有在确认相关素材不会影响结果，或工作电脑可以访问这些素材时才使用。这个选项不会修复缺失素材。

## 5. 提交第一个任务

1. 在提交电脑进入“渲染任务”。
2. 拖入 `.blend`，或使用添加按钮选择文件。
3. 等待“读取并检查工程”和“创建任务”完成。
4. 阅读素材警告，处理需要补齐的文件。
5. 等待工程同步到参与电脑。
6. 在参数窗口选择 Blender 软件配置。
7. 确认起始帧、结束帧和步长。默认值来自工程。
8. 选择每包帧数，范围 1–20，默认 5。
9. 选择测试帧并开始测试。

先用一个短帧段完成首次验证。检查至少一张测试图以及需要的合成器输出。任务显示“测试完成”后，右键选择“全速渲染”，或使用任务详情中的绿色播放按钮。

“全速渲染”开始完整帧范围。远端电脑仍按空闲策略接单。提交电脑必须保持运行，才能继续分配任务和收集结果。关闭窗口时选择“最小化到通知区域”可以保持程序运行。

## 6. 查看输出和任务状态

任务详情显示每帧的状态、执行电脑、时长、开始与结束时间、日志和错误。

| 显示状态 | 含义 |
| --- | --- |
| 等待或排队 | 该帧尚未开始；工作电脑可能正在打开工程或处理包内前一帧 |
| 渲染中 | Blender 已开始该帧 |
| 已完成 | 该帧的结果已收回并保存 |
| 失败 | 查看该帧错误与日志 |
| 已停止 | 任务被停止；可恢复尚未完成的帧 |

主图写回提交电脑上由工程设置确定的输出路径。File Output 节点的结果写回对应节点目录。没有帧号的合成器文件名会补六位帧号，避免连续帧相互覆盖。

可在详情中预览 PNG/JPEG。OpenEXR 等格式通过本机 Blender 转换后预览。使用资源管理器按钮定位源工程或输出文件。重新渲染相同路径可能替换已有结果，保留旧结果时请先更换输出目录。

## 7. 控制任务和参与电脑

| 操作 | 结果 |
| --- | --- |
| 停止 | 正在渲染的当前帧完成后停止后续工作；已完成结果保留 |
| 恢复渲染 | 重新排队已停止的帧 |
| 重试 | 重新排队失败的帧 |
| 编辑渲染主机 | 加入或移除当前任务的参与电脑 |
| 删除 | 删除任务记录和托管工程数据；保留原始工程及工程输出目录中的成品 |

新加入的电脑会先同步该任务工程，再参与调度。移除电脑会停止后续派发。任务列表支持 Ctrl/Shift 多选，可批量开始完整渲染或删除。

关闭共享后，本机不再接收新的远端任务。电脑恢复键鼠操作时，已经开始的当前帧仍会完成，然后交回任务包中尚未执行的帧。

## 8. 设置和本地数据

| 设置 | 作用 |
| --- | --- |
| 空闲时间 | 决定本机何时允许接收远端渲染任务 |
| Blender 路径与软件配置 | 决定工程读取及本机渲染使用的 Blender |
| 工程存储 | 存放托管工程、缓存、预检副本、预览和临时结果 |
| 主题 | 跟随系统、浅色或深色 |
| 关闭行为 | 每次询问、退出、最小化到通知区域 |
| 开机自启 | 登录当前 Windows 用户时启动 RenderMesh |
| 静默自启 | 开机自启时进入通知区域 |

配置、任务记录、日志和更新助手默认在 `%LOCALAPPDATA%\RenderMesh`。日志在其 `logs` 子目录。工程存储初始也使用该根目录。

更换工程存储时，选择一个空目录。程序暂停节点服务，复制数据并校验，成功后切换位置。迁移期间保持程序运行。最终输出目录不随此设置迁移。

备份前先停止任务并退出程序。备份数据目录、单独设置的工程存储目录、源工程和输出目录。`config.json` 含节点凭证，不要上传到公开仓库或问题反馈。

## 9. 更新

从 [Releases](https://github.com/FELIXDAD/RenderMesh/releases/latest) 下载新版本。停止任务并退出 RenderMesh 后，替换程序文件。保留数据目录。

同一匹配组内的节点也可以发现其他已认证节点上的新版本。看到更新提示后选择“立即更新”，程序会校验、替换并重启。局域网更新依赖对同组电脑的信任。

建议同一组电脑统一使用当前版本。

## 10. 常见问题

| 现象 | 处理 |
| --- | --- |
| 找不到其他电脑 | 确认双方程序运行、匹配 ID 相同；检查 UDP 8390、TCP 8391；尝试手动 IPv4 连接 |
| 节点在线却不渲染 | 检查共享开关、空闲时间、Blender 路径、版本和 GPU；确认节点已加入当前任务且完成同步 |
| 只有本机渲染 | 远端节点可能忙碌、活跃、未开启共享或环境不匹配；查看节点状态和任务日志 |
| 导入很慢 | 检查文件体积、外部素材数量、磁盘与网络速度；大工程的读取和传输需要时间 |
| 导入提示缺失素材 | 在 Blender 修复路径并重新保存；确认 `tex` 布局与相对路径 |
| Cycles GPU 任务被拒绝 | 在该电脑的 Blender 中配置可用 GPU 和驱动，确认非 CPU 设备已启用 |
| 测试帧失败 | 查看该帧日志；检查 Blender 版本、插件、素材、GPU 和输出权限 |
| 一直排队 | 查看工作电脑是否正在加载工程、是否达到空闲阈值，以及是否有可用参与电脑 |
| 合成器输出缺失 | 确认工程启用合成、File Output 节点未静音且能在 Blender 中产出；检查日志与磁盘空间 |
| 关掉窗口后节点离线 | 关闭行为可能设为退出；改为最小化到通知区域 |
| CLI 返回退出码 3 | 先打开桌面程序或运行 `serve`；确认命令和节点使用同一数据目录 |

反馈问题时，提供 RenderMesh 版本、Windows 版本、Blender 版本、渲染引擎、复现步骤和相关日志片段。先删除凭证、私人路径和工程内容。可公开的最小复现工程更便于定位问题。
