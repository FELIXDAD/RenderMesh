# 安全说明

- RenderMesh 面向可信公司内网；不要把 UDP 8390 或 TCP 8391 直接暴露到互联网。
- 初次运行生成 128-bit 内部随机集群凭证和独立的六位可见邀请码。任务和结果接口用常量时间比较验证内部 `X-RM-Token`；UDP 发现把节点自身 IPv4 地址列表、随机 nonce、硬件与状态纳入 HMAC-SHA256 签名，接收端验证实际源 IP，派发前还要求该端点完成新的 HMAC 挑战。六位邀请码不会用于发现签名，也不会广播。
- 六位邀请码只用于可信公司 LAN 上的人工配对。新节点必须由用户明确填写一台已加入集群的可信 `IPv4:端口`，服务端对每个来源 IP 每分钟最多接受六次尝试。邀请码空间本身较小，不能替代企业身份认证；不要向陌生 IP 发起配对。
- 共享算力默认关闭；关闭时即使集群码正确也拒绝远端任务。
- 任务 ID 只允许字母、数字、`-`、`_`，接收文件总是写到内部生成的目录，避免路径穿越。
- 接收采用临时文件和原子替换；请求体上限为 100 GiB。
- 任务/结果上传的 socket 阻塞等待上限为 5 秒，数据提供器检查退出信号；Blender 预检、兼容性检查和正式渲染也支持中止。
- 每次远端派发使用独立随机 attempt token。Origin 只接受当前 Assigned 租约的结果，过期 Worker 的迟到结果返回 409。
- 正式渲染使用 Blender `--disable-autoexec`，避免工程自动执行 Python。但 `.blend`、插件、驱动和原生库仍必须视为公司内部受信内容。
- 数据面当前是内网明文 HTTP。VLAN 内主动抓包者可能观察集群码和工程；生产范围扩大前应增加设备证书/mTLS 或隔离渲染 VLAN。
- 内部集群凭证或邀请码泄露后，应在所有节点重新配对。当前版本没有中央轮换服务。
- EXE 未做商业代码签名。正式全公司部署前建议由 IT 代码签名，并通过域策略只允许专用/域网络端口。
