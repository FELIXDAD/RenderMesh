# RenderMesh

RenderMesh 是面向公司内网 Windows 10/11 工作站的轻量级 Blender 帧级渲染农场。最终程序是约 1.6 MB 的原生 C++ 单文件 `RenderMesh.exe`（分发 ZIP 约 0.8 MB）：不需要 Python、.NET、安装器或管理员权限，解压后双击即可运行。

## 已实现

- 每台电脑同时是任务提交端和 Worker，通过每张网卡的定向 UDP 广播自动发现同一局域网节点；多网卡或广播受限时可手动填写局域网 IP。
- 共享算力默认关闭；用户主动开启后才接收别人的任务。
- 所有远端渲染（Eevee、Cycles GPU 和 Cycles CPU）只在电脑连续空闲（默认 3 分钟）后接单；若键鼠恢复，会完成当前帧，再停止包内后续帧并安全重派。
- 不使用 CPU 限速；电脑处于活跃状态时不接受远端渲染任务。
- 动画按实际帧序列组成每包 1–20 帧、默认 5 帧的任务包（末包可更少）；已打包的 `.blend` 先按 SHA-256 查询 Worker 缓存，缺失时以 8 MiB 分块断点续传。每包只启动一次 Blender，但每帧一完成就立即回传文件并更新该帧状态，不等待包内其余帧。
- Blender 批处理清单为包内每一帧分别记录真实开始/结束墙钟时间。包被 Worker 接收后，尚未开始的帧保持“排队中”且时长为 `-`；Blender 真正开始某帧时，Worker 才用带 attempt token 的 `/v1/frame-start` 将该帧切到“渲染中”并开始计时，最终结果再携带真实结束时间。因此任务详情不会把前面帧、排队或结果上传时间累计到后续帧。
- 协议 v15 显式声明并签名单帧开始事件能力。新 Origin 遇到未声明该能力的旧 Worker 时自动把该节点的包限制为一帧，并沿用兼容计时显示；全部节点升级到 0.2.28 后可获得精确的实时开始时间。若用户在 Blender 尚在打开工程时停止任务，新 Worker 会终止该启动进程、清空任务包占用并立即恢复可接单；已经真正开始的当前帧仍按策略完成后再停。
- Worker 渲染任何远端任务期间检测到键鼠恢复时，不杀掉正在渲染的当前帧；当前帧完成并回传后，停止包内后续帧并交回队列。
- Worker 会拒绝“Blender 退出码为 0、但没有生成任何请求帧”的假成功；若它发生在启动后 10 秒内，会自动重启该任务包一次，再次失败则把明确错误和日志尾部回传给 Origin。
- 首次安装或升级 Blender 后，RenderMesh 会在第一次使用前执行一次最长 15 秒的无界面初始化；仅当 `userpref.blend` 不存在时创建默认偏好，已有配置不会被覆盖。Cycles GPU 运行时只启用一个后端，优先保留用户选择，否则按 OptiX、CUDA、HIP、oneAPI 探测。
- 预检完成后的工程进入任务目录时，对 Windows Defender、同步盘、索引器或 Blender 引起的短暂共享冲突做最长 5 秒重试；真实权限/路径错误仍立即报告，持续占用超时后不会假装提交成功。
- 拖入或选择 `.blend` 后，主界面会显示覆盖全窗口的两阶段加载进度并阻止重复操作：读取并检查工程（只启动一次 Blender）、创建任务。完成或失败后自动关闭；窗口关闭仍会安全中止后台 Blender。读取成功后自动填写工程起始帧、结束帧和步长，提交前仍可手动调整。
- 保留工程的主输出格式和路径；活动场景及其节点组内的 File Output 节点会递归记录场景、稳定节点位置、文件名模式和 AOV/输出项（支持 Blender 5.2 `file_output_items` 与旧版 slots），启用的节点在 Worker 沙箱内完整采集，每帧以多文件结果包回传，并由 Origin 写回预检时记录的对应目录。`{blend_name}` 会按原工程名解析；没有帧号的合成器文件名会补六位帧号以防覆盖。muted 节点或关闭工程合成时保留兼容定位但不要求产出。
- 若源 `.blend` 同级存在 `tex` 文件夹，`tex` 内的素材不会被打包进 `.blend`，而是直接从原文件流式写入安全工程包（写入的同时计算 SHA-256），按同一个哈希断点续传并在 Worker 缓存中还原为 `source.blend + tex\...`；相对素材路径保持不变。普通工程仍只发送单个 `.blend`，不会增加额外打包开销。
- Fluent 风格原生分栏界面以 `#4D45E9` 为主色，支持跟随系统/浅色/深色；左上角滑动式开关随时显示本机是否共享算力。
- 服务器页显示在线电脑、CPU/GPU 型号、信任状态、共享/活跃/空闲状态和已分配帧数。远端渲染固定采用“仅空闲”策略，因此不再重复显示没有可选值的“调度策略”列；设置中的无操作秒数仍决定本机何时进入可接单状态。远端节点直接发布经过签名的“已达到本机空闲阈值”状态；`0 秒`会显示为黄色“活跃 · 等待”，只有达到该电脑自己的阈值才显示绿色“已空闲”。本机或远端接到任务包但 Blender 尚未开始当前帧时显示“排队中”，真正进入单帧渲染后才显示“正在渲染”。
- 渲染参数窗口管理可复用的软件配置（配置名称、渲染系统、渲染软件、安装路径），记住上次选择，并把所选 Blender 可执行文件固化到当前作业的本机执行配置；旧版单一 `blender_path` 会自动迁移为默认配置。
- 渲染任务页精确保留 10 个可见队列槽位并可滚动；支持 Ctrl/Shift 多选后批量全速渲染或批量删除。任务详情列出每帧状态、渲染电脑、任务包、时长、开始/结束时间和错误，可直接预览 PNG/JPEG，并通过已安装的 Blender 安全转换预览 OpenEXR 等工程输出格式；也可在资源管理器中定位源 `.blend` 或选中输出。测试完成时，右下角在两个资源管理器按钮右侧显示绿色播放按钮；进入测试或正式渲染后同一动作槽只显示红色停止按钮，二者不会同时出现。任务停止后，列表右键“恢复渲染”保留已完成输出，只把已停止帧清除旧租约后重新排队。
- 每个任务的右键菜单始终提供“编辑渲染主机”。独立窗口列出本任务当前参与电脑和后来新加入的可用电脑，支持 Ctrl/Shift 多选、全选、反选、明确的“加入/断开”、失败重试和同样的右键操作；断开节点会撤销后续派发，加入节点会先完成该任务工程同步再进入调度池。窗口内的列会随宽度重新分配，关闭按钮固定在右下角。
- Worker 会持久记录本机替其他电脑渲染过的任务包、分配帧/完成帧、来源电脑、状态和时间；本机贡献列表支持多选并只清理所选历史元数据。
- 六位匹配 ID 可直接查看和编辑；同一局域网内的全新节点只需输入相同 ID 即可自动发现并完成配对，无需预先知道 IP。每台电脑都会同时使用网卡定向广播和 TTL=1 的局域网组播直接公布自己的地址，并直接向实际节点读取算力、占用和任务状态；任何一台测试机都不是中心服务器，退出后不会中断其余节点互相发现。认证节点目录只作为广播被网络设备拦截时的候选 IP 补充，不能替其他电脑续期在线或任务状态。修改 ID 后立即撤销旧节点信任并轮换内部随机长凭证，只有 ID 相同才会重新连接。
- 配置、日志、更新器与小型任务数据库保存在 `%LOCALAPPDATA%\RenderMesh`；任务工程、远端缓存、上传临时文件、预检副本、预览缓存和失败结果统一使用设置页可修改的“工程存储”目录。更改位置时先暂停节点服务，在后台完整复制并逐文件执行 SHA-256 校验，再原子切换配置并清理旧目录；取消或校验失败时继续使用原目录。
- 关闭按钮可设置为每次询问、直接退出或最小化到通知区域；询问面板可“记住本次选择”。内部确认面板打开期间，后台状态刷新只记录为待处理，不会让列表穿透到面板上方；关闭面板后合并刷新一次。托盘图标使用简化 RenderMesh 网格主体和 Fluent 状态角标：绿色勾表示空闲、紫色同步箭头表示渲染、红色感叹号表示错误；悬停显示本机任务状态与进度，单击恢复窗口，右键可切换共享或退出。

## 零安装使用

1. 把发布 ZIP 发给办公室电脑，解压后双击 `RenderMesh.exe`。
2. Windows 第一次询问网络权限时，只允许“专用网络/域网络”。
3. 程序会自动查找标准安装目录、PATH 或解压目录 `Blender\blender.exe`。未检测到 Blender 时会提示读取官方镜像的近期 Windows x64 MSI，版本选择器标出 LTS；选择下载目录后，只有长度和官方 SHA-256 均通过才启动 Windows Installer。设置页可随时“安装 / 切换 Blender 版本”，自定义位置也可在软件配置中手动选择。没有 Blender 的节点仍可连接并显示在线，但不会进入工程同步或渲染派单池。
4. 第一台电脑复制六位匹配 ID，其他电脑输入相同数字；同一局域网内会自动发现并配对，不需要先填写 IP。修改 ID 后旧连接会立即失效，两端改为同一新 ID 后才会恢复。
5. 愿意提供算力的电脑打开左上角“共享本机算力”开关，按钮会明确显示“已开启”。
6. 如果服务器列表没有自动出现另一台电脑，在对方服务器列表的“本机”行查看真实局域网地址，在本机“手动连接”中填写，例如 `192.168.28.28:8391`；不要填写 `127.0.0.1`，它始终表示当前电脑。
7. 进入“渲染任务”，拖入 `.blend` 或点击右下角添加按钮；两阶段加载面板会显示当前读取检查/建任务步骤并暂时阻止其他操作。本地预检通过后先同步工程到参与电脑，在参数窗口选择 Blender 软件配置并确认帧范围、每包帧数和测试帧。在线节点优先，没有可用节点时由本机渲染；达到“测试完成”后右键任务选择“全速渲染”。右键“编辑渲染主机”可随时增加新节点或移除参与者；已停止任务可选择“恢复渲染”，不会重做已经完成的帧。Ctrl/Shift 多选可批量全速渲染或删除。输出格式完全使用工程设置。
8. 第一次只需把 0.2.29 ZIP 发到所有电脑。以后把更新版放到并启动任意一台已配对电脑，其余节点会出现局域网更新提示；选择“立即更新”后程序自行校验、替换并重启。

程序关闭后该电脑就离线；不安装后台服务，不修改启动项。

## 提交前的硬预检

RenderMesh 不直接分发用户选择的原始工程，而是先调用本机 Blender：

1. 检查图像、字体、声音、影片、链接库、缓存和体积文件，支持 `//` 相对路径、UDIM 与序列模式。
2. 有任一外部文件丢失时先提醒并在界面列出路径；用户可显式选择“无视警告”，把是否继续的决定权交给提交者。
3. 只在需要时打包：`tex` 文件夹内的素材由工程包传输，路径保持 `//tex/...` 相对形式；其他可打包的外部素材（图像、字体、声音、链接库、体积）才由 Blender 打包并另存一个临时 `.blend`。没有需要打包或改写的路径时不另存，任务直接使用原工程的快照。选择“无视警告”后跳过全部预检警告，直接准备任务。
4. 记录 Blender 主/次版本和渲染引擎。Worker 必须使用相同主/次版本与引擎；Eevee/Cycles GPU 还必须通过对应 GPU 探针。
5. 发起端预检不会渲染提交范围内的任何帧；工程能否真实出图由随后只在参与 Worker 上运行的测试帧确认。这样大帧段不会在导入阶段被本机逐帧执行。
6. Cycles GPU 工程只会交给检测到已启用非 CPU Cycles 设备的 Worker；没有可用 GPU 的节点会拒绝接单，避免静默退回 CPU。

`.blend` 本身没有标准化、可靠的“本工程实际依赖哪些第三方插件”清单，而发起端所有已启用插件也不等于工程依赖。为避免大量误拦截，当前版本不采集、不比较插件安装/启用/版本清单；若工程确实依赖第三方插件，请给 Worker 统一环境，并用只在 Worker 执行的测试帧先验收。

## 技术与开源基础

架构参考 [OpenCue](https://github.com/AcademySoftwareFoundation/OpenCue) 的 Frame 调度和 [CueNIMBY](https://github.com/AcademySoftwareFoundation/OpenCue/tree/master/cuenimby) 工作站自愿接单模型。网络层是程序内置的精简 HTTP/1.1 实现（与旧版节点线上兼容）；JSON 使用 MIT 许可证的 [nlohmann/json](https://github.com/nlohmann/json)。详情见 `THIRD_PARTY_NOTICES.md`。

## 构建与自检

开发构建使用便携版 llvm-mingw。同一份源码产生两个程序：分发用的 `RenderMesh.exe`，以及带 `-DevTools` 的 `RenderMesh-dev.exe`（额外包含内置自检、UI 回归钩子和开发命令，不分发）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\native\build.ps1 -Configuration Release
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\native\build.ps1 -Configuration Release -DevTools
Start-Process .\native\build\Release\RenderMesh-dev.exe -ArgumentList '--self-test','--no-dialog' -Wait
```

`native\package.ps1` 会构建这两个程序，用 `RenderMesh-dev.exe` 运行自检和 UI 回归，再用分发的 `RenderMesh.exe` 运行全部网络、更新和旧任务导入测试。

内置自检覆盖五帧分包及逐帧独立计时、零帧假成功拒绝与快速空产出重试判定、Blender 首次无界面初始化参数和单一 GPU 后端选择约束、配置持久化、HMAC、文件 SHA-256、七天缓存清理、忽略旧插件缓存字段、可取消的入站传输和多文件结果包、贡献历史重载、2 MiB 流式传输、仅空闲接单策略、两个真实 HTTP 节点之间七帧分包/缓存/多输出回传、任务停止/恢复栅栏、动态参与节点、`tex` 工程包缓存、局域网更新清单与下载、掉线重派及过期回传拒绝（渲染器使用测试桩）。真实 Blender 预检与渲染验证步骤见 [验证记录](docs/VERIFICATION.md)。

## 命令行

`RenderMesh.exe` 不带参数时打开桌面程序；带命令时执行一次操作、输出结果后退出，便于脚本和 Claude、Codex 等智能体调用。帮助文本使用 ASD-STE100 简化技术英语：

```powershell
RenderMesh.exe help
RenderMesh.exe help submit
RenderMesh.exe inspect D:\Projects\shot.blend --json
RenderMesh.exe submit D:\Projects\shot.blend --name shot010 --wait --json
RenderMesh.exe test <job-id> --frames 1-120 --test-frames 1,60,120 --json
RenderMesh.exe start <job-id> --json
RenderMesh.exe serve
```

- 命令：`help`、`version`、`status`、`jobs`、`job`、`inspect`、`submit`、`test`、`start`、`stop`、`resume`、`retry`、`delete`、`serve`。
- `--json` 输出单行 JSON，`ok` 表示是否成功，失败时 `error` 给出原因；`--data-dir` 指定数据目录。
- 退出码：0 成功；1 操作失败；2 命令或参数错误；3 本机没有运行 RenderMesh（先打开桌面程序或运行 `serve`）。
- `inspect` 在命令进程内直接运行，不需要节点；其余任务命令通过只接受本机回环地址的控制接口交给正在运行的 RenderMesh 进程。
- `serve` 以无窗口节点运行，Ctrl+C 停止；同一数据目录同时只能有一个 RenderMesh 进程。

## 当前边界

- 只支持动画按帧拆分，不拆分同一帧的 Cycles samples。
- 每台 Worker 同时运行一个 Blender 进程；每个任务包默认最多连续渲染 5 帧。
- 已打包工程使用完整 SHA-256 作为 Worker 缓存键；同一工程只在缓存缺失或 Blender/引擎/GPU 兼容条件变化时重新上传。最后一次任务执行超过七天后自动清理工程缓存；每帧输出临时目录在回传后立即删除，回传失败只保留小型诊断记录。
- HTTP 数据面没有 TLS，集群码也不是企业身份系统；只应部署在可信公司 LAN/VLAN，不能暴露到互联网。
- 为避免限速能力和渲染引擎差异造成不一致，所有远端渲染统一采用“仅空闲运行”策略。
- EXE 当前未做商业代码签名，Windows SmartScreen 可能显示未知发布者；发布到全公司前建议由 IT 使用公司证书签名。

更多实现边界见 [架构](docs/ARCHITECTURE.md) 与 [安全说明](docs/SECURITY.md)。
