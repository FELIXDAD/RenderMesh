RenderMesh 0.2.10（Windows x64）

无需安装、无需 Python、无需 .NET、无需管理员权限。

1. 解压整个 ZIP，双击 RenderMesh.exe。
2. 第一次 Windows 网络提示只允许“专用网络/域网络”。
3. 状态栏确认 Blender“已检测”；若未检测，手动选择 blender.exe。
4. 第一台电脑复制集群邀请码，其他电脑粘贴同一邀请码并保存。
5. 愿意提供算力的电脑打开左上角“共享本机算力”开关，按钮会明确显示“已开启”。
6. 未自动发现时，在“手动连接”填写对方“本机”行显示的局域网 IP:8391；不要使用 127.0.0.1。
7. 进入“渲染任务”，选择 .blend；程序会自动读取并填写工程的起始帧、结束帧和步长，确认后点击“预检并提交渲染”。输出格式和路径完全使用工程设置。

任务详情可查看每帧状态/时间、预览图像、定位源工程与输出；双击任意单帧可打开 Blender 日志详情，渲染中会增量刷新，完成、失败或停止后保留最终日志。OpenEXR 等 Windows 无原生解码器的格式会由已安装的 Blender 生成预览。“本机贡献”会保留这台电脑替别人渲染过的任务包历史。

预检会自动检查并打包外部素材，同时记录 Blender 主/次版本和渲染引擎。
合成器 File Output 节点（含 Blender 5.2 AOV/多层 EXR 输出项）会一起记录；每帧完成后立即从 Worker 回传到工程设置的原目录。若工程文件名模式没有帧号，RenderMesh 会补六位帧号，避免任务包内多帧互相覆盖。
预检还会对提交范围内每一帧做低分辨率真实渲染；插件、节点、相机或引擎执行错误会在分发前阻止任务。帧数越多，预检耗时越长。
缺素材、无法打包、Blender 版本/引擎不兼容或 GPU 探针失败时会阻止渲染。插件安装、启用和版本清单不再比较；依赖第三方插件的工程建议先提交少量帧验收。
如果远端 Blender 在启动后立即正常退出却没有生成任何帧，Worker 会自动重启该任务包一次；再次失败会把明确错误和 Blender 日志回传到任务详情。
首次安装或升级 Blender 后，RenderMesh 会先在后台完成一次无界面初始化；仅在偏好文件不存在时生成默认配置，15 秒未完成会终止进程并报告错误。Cycles GPU 会在每个进程内选择一个可用后端，不覆盖已有偏好。
提交时若 Blender、Windows Defender、同步软件或索引器短暂占用刚打包的工程，RenderMesh 会自动等待并重试，不会因一次共享冲突直接丢弃任务；持续占用或真实权限错误仍会明确提示。

默认策略：
- 共享算力：关闭
- 所有远端渲染：连续 180 秒无键鼠输入后才接单，键鼠恢复后完成当前帧，其余帧停止并重派
- Eevee：Worker 必须同时具备可用 Eevee 引擎和 Windows GPU 图形设备，否则拒绝任务
- Cycles GPU：Worker 必须检测到已启用的非 CPU Cycles 设备，否则拒绝任务
- 不使用 CPU 限速；电脑活跃时不接受任何远端渲染任务

数据和结果：%LOCALAPPDATA%\RenderMesh
端口：UDP 8390（发现），TCP 8391（任务/结果）

注意：只用于可信公司内网，不要暴露到互联网。关闭窗口后本机即离线。
